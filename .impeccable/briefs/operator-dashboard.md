# Operator Dashboard Surface Brief

## Mode

Operate. Students and instructors need to scan sensor truth, device/network state, activity history, and a safe control surface.

## Direction contract

- **World:** Fieldwork passport; the world lends a grounded pine/paper palette, legible humanist type, compact evidence density, and one verification-stamp interaction.
- **First viewport:** Standard dashboard shell with Station, Trends, and Progress navigation. Lead with actual/demo mode, online/stale status and last-update age; show the three sensor families and a motion event summary; keep indicator actual state and ON/OFF controls visible; show verified milestones below primary device information.
- **Visitor path:** Identify actual device status, inspect current readings and a trend, issue a command, confirm the acknowledgment and actual state, then review earned evidence milestones.
- **Signature interaction:** A verified sensor, command, or 30-minute-run milestone earns a small stamp that links to its source evidence.
- **Cross-surface reach:** Reuse the same sensor names, units, status vocabulary, and evidence IDs in Grafana and the lab report.
- **Honest risk:** A collectible motif can trivialize monitoring; keep it secondary and never award progress for missing or simulated live data without a visible demo label.

## Data and states

Actual mode reads only from the local gateway. Demo mode displays a persistent DEMO label and deterministic fixture data; its controls are simulated and cannot publish MQTT. Actual mode must show offline/stale/unknown when the gateway or board is unavailable. Requested output, acknowledgment, and actual output remain distinct.

## Responsive and accessible behavior

Reflow to one column on narrow phones and retain status, sensor readings, and control access. Use 44 px minimum touch targets, keyboard-visible focus, semantic labels, screen-reader announcements for acknowledgments and connectivity, and a reduced-motion alternative.
